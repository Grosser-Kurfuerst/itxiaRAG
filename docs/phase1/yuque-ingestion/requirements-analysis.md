# 第一批需求分析：操作教程、工具条目、知识科普

本文分析第一批导入的三类语雀文档，给出需求、验收口径与类别识别可行性结论。技术实现见[技术方案](technical-design.md)；范围与批次见[概览](overview.md)。统计来自 2026-10-08 的公开快照，规范化后按去空白字符数计算，只用于说明设计依据。

## 1. 背景与目标

IT 侠语雀是社团最主要的知识沉淀：在线互助常见问题集（help）、教程与记录系列（article）、培训手册（textbook）等。当前知识库已支持原文导入和评测、购机指南、经验三类结构策略，但语雀文档的体裁和导出格式与它们不同，直接套用会出现章节错切、样式标签和截图地址进入向量、标题被误判等问题。

第一批目标：

1. 把操作教程、工具条目、知识科普／对比／速查三类文档按各自结构导入，检索命中后返回语义完整的章节上下文、风险提示和出处。
2. 导入时按文档类别在运行时选择预处理流程；类别可由代码识别的部分自动判定，其余由人工清单指定。
3. 复用现有原文预处理链、统一 DTO、导入与检索服务，不改变现有 API 和已有三类策略的行为。

## 3. 语雀导出的共性问题

### 3.1 方言与格式

语雀 Markdown 导出（以及预期的 OpenAPI `body`）不是标准 Markdown。下表统计第一批 74 篇：

| 现象 | 数量（涉及篇数） | 不处理的后果 |
| --- | --- | --- |
| `<font>`、`<span>`、`<u>`、`<sup>` 等样式标签 | 806（34） | 标签进入正文与向量；28 处包在标题外，标题文本带 HTML |
| 提示块 `:::tips/info/success/colorN` | 91（32） | `:::` 行成为正文，提示与正文混在一起 |
| 提示块 `:::warning`、`:::danger` | 31（14）、3（3） | 警告失去级别，无法进入父段 warnings |
| 单行 HTML 折叠块 `<details><summary>…` | 8（2） | 整行 HTML 进入正文 |
| 空标题 `#### `、空加粗 `****` | 19（10）、29（16） | 产生“####”等无意义正文 |
| 整行加粗 | 101（29） | 现解析器一律视为二级标题，大量强调句会切断章节 |
| 文内锚点链接 `[…](#xxxx)` | 16（8） | 导出后锚点失效 |
| 删除线 `~~…~~` | 48（18） | 多为玩笑或作废内容 |
| 图片 `![](cdn…)` 与 `<img>` | 590（62），有说明文字的仅 10 处 | 现 MarkdownParser 不识别图片，CDN 地址进入正文和向量 |
| 尖括号占位符，如 `<你的Windows用户名>` | 33（6） | 用通用正则去标签会误删命令参数 |
| 表格单元格内 `<br/>` | 88（9） | 表格行需保持单行 |
| 引用行 `>`（含空引用行） | 499（34） | `>` 前缀和空引用行进入正文 |
| 导出不含文档标题 | 全部 | 首个 H1 常是章节名（如“一、准备工作”） |

另外，Markdown 导出会丢失表格单元格底色。`Windows系统功能快速查阅表` 用红、黄、绿底色标注命令风险，导出后风险等级消失，原始 lake 格式中仍有。

### 3.2 现有实现的缺口

| 位置 | 现状 | 对语雀文档的影响 |
| --- | --- | --- |
| [MarkdownParser](../../../ingestion/parsers.py) 第 62 行 | 整行加粗一律视为二级标题 | 强调句被当成章节边界，并把 H3 小节提升为二级 |
| MarkdownParser | 不识别图片、引用块、提示块，空标题按正文处理 | 见上表 |
| [`_without_document_heading`](../../../ingestion/strategies.py) 第 85 行 | 首个 H1 视为文档标题并移出正文 | 语雀导出的首个 H1 多为章节名，会丢失章节结构 |
| [HeadingSectionsStrategy](../../../ingestion/strategies.py) 第 117 行 | 固定按某一级标题切父段 | 语雀文档最浅标题从 H1 到 H3 都有，超长章节不会下钻，过短章节不会合并 |
| [ReviewStrategy._chunks](../../../ingestion/strategies.py) 第 175 行 | 自然段合并成检索块的逻辑可用，但写在评测策略内部，并带有评测专用的栏目层级判断 | 新策略需另写合并逻辑，可复用其中的相连判断函数 |

## 4. 三类文档分析

### 4.1 操作教程

**典型文档**：Windows 安装／重装教程、新电脑验机与设置指南、更改用户名、数据清理与备份、远程连接、Office 安装激活、培训手册中的拆机、清灰与社内装系统。

**结构特征**：

- 篇幅长，章节层级 1～4 级。最浅标题有的是 H1（“准备篇／安装篇／激活设置篇”），有的是 H2（“一、二、三”）。
- 顶层章节大小差异大：p10 只有 90 字（如“6.0、确定没问题了？”“引用”），p90 接近 3000 字，最大 7036 字；16 个顶层章节超过 2500 字。
- 步骤多写成“5、点击……”式段落（276 段），而不是 Markdown 列表；步骤之间夹截图和补充说明。
- 有条件分支（“可进入系统时／无法进入系统时”）、高危提示（“高危操作，小白请在指导下进行”）、时效说明（“四、初始化电脑（2025.11 更新）”）。
- 截图密集：370 张，`install_win10` 一篇就有 87 张，几乎都没有说明文字。
- 命令和占位符要原样保留，例如 `netsh winsock reset`、`<你的Windows用户名>`。

**检索场景**：“Win11 怎么跳过联网”“怎么改 Windows 用户名”“C 盘满了怎么清理”“U 盘装机盘怎么做”。用户需要拿到某一章节的完整步骤、它的前提和风险提示，并知道有截图可以去原文查看。

### 4.2 工具条目

**典型文档**：help “IT侠常用工具大全”目录下的 28 篇（如“文件占用查看：WizTree”“装机盘制作：rufus”），article 中的插件推荐，以及培训手册的“常用软件”合集。

**结构特征**：

- 多数很短：中位数 207 字，21 篇没有任何标题；不少正文只有一两句话加一张截图（如“软件卸载：GeekUninstaller”95 字）。
- 标题格式稳定为“用途：工具名”，目录二级分组就是工具分类（文件占用和系统清理、硬件检查测试软件、装机盘制作和PE 等）。
- 少数长文有关键警告，如 Snappy Driver Installer 提醒联想笔记本不要安装 Alps 触摸板驱动。
- 合集文档按“分类 > 工具”组织（培训手册“常用软件”有 4 个分类、十几个工具小节）。
- 官网和下载链接是核心信息。
- 时效风险最高：22 篇最后更新在 2020 年。

**检索场景**：“查看哪个文件夹占空间用什么软件”“有没有彻底卸载 Office 的工具”“SDI 装驱动要注意什么”。正文很短，召回主要依赖工具名、用途和分类；同类工具最好一起召回，便于比较。

### 4.3 知识科普／对比／速查

**典型文档**：Windows 版本与激活详解、C 盘文件夹功能与分布、纯净镜像下载途径比较、Office 套件选择、笔记本硬件科普、黑话指南、Bitlocker 概述、网络基础与问题、Windows 系统功能快速查阅表、分层 FAQ。

**结构特征**：

- 按“主题 > 术语／小节”组织，叶子小节很碎：中位数 159 字，229 个叶子小节中 68 个不足 100 字（如“频率”“拓展性”各一两句）。
- 3 篇把文章标题重复成唯一的 H1 包住全文（如“IT侠笔记本硬件科普——核心配件篇”），真正的章节在 H2。
- 比较表和速查表 11 张、100 行，例如功能 → 命令、品牌 → 售后网站、版本对比。
- 分层 FAQ 达 5 级标题、60 个 H4，按“简明／三层次”区分读者水平。
- 有时间限定表述，如“目前（2022年初）价格很高”。

**检索场景**：“数字权利激活是什么”“ProgramData 和 Program Files 有什么区别”“重置 Winsock 用什么命令”“独显和核显区别”。用户往往问某个术语或表格中的一行，系统需要精准命中，再返回所在主题作为上下文。

## 5. 需求

### 5.1 通用功能需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| Y-G01 | 语雀方言规范化：样式标签、提示块、折叠块、空标题、空加粗、锚点链接、删除线、图片、表格内换行按第 3.1 节处理；不得删除尖括号占位符、代码块和命令 | 74 篇试运行后正文不含样式标签、`:::` 和 CDN 图片地址；占位符和代码块与原文一致 |
| Y-G02 | 文档标题取自语雀元数据，不从正文推断；去掉【推送归档】等前缀和 ⭐ 难度标记，原标题存入元数据 | 父段与文档标题不出现“一、准备工作”等章节名误判 |
| Y-G03 | 章节结构自适应：以文档实际最浅标题为父段起点，识别包裹全文的单一标题，超长章节下钻，过短章节合并 | 第一批没有因标题级别不同导致的空父段或整篇单父段（无标题短文除外） |
| Y-G04 | 风险提示：warning／danger 提示块进入所在父段 warnings；第一个标题前的全局提示进入文档 warnings | 检索结果的 warnings 含原文警告 |
| Y-G05 | 截图：无说明截图不进入正文和向量；记录数量，提示查看原文；有说明的保留说明文字 | 父段正文不含图片地址；metadata 有截图数量 |
| Y-G06 | 稳定身份与更新：来源用语雀文档数字 ID，保留原文链接；同一文档重新导入按稳定 key 更新 | 重复导入 `reused=true`；修改一个章节不影响其他章节的父段 key |
| Y-G07 | 运行时类别选择：每篇文档按类别选择预处理流程；人工清单优先，可代码识别的类别由清单中的目录规则自动判定，未登记的不导入 | 清单条目、目录规则和未登记文档都在报告中可追溯 |
| Y-G08 | 排除与去重：重复副本、废弃、索引、说明文档和非第一批类别跳过并报告原因 | 报告中每篇文档都有明确状态 |
| Y-G09 | 试运行：只预处理不编码不保存，输出每篇父段数、子块数、警告和错误 | 不配置 Embedding 也能对 74 篇试运行 |
| Y-G10 | 可见范围按知识库或单篇配置；当前全部设为 public，internal 保留备用 | 普通调用方检索不到 internal 文档 |

### 5.2 分类需求

| 编号 | 类别 | 需求 | 验收 |
| --- | --- | --- | --- |
| Y-T01 | 教程 | 父段对应一个章节，标题带章节路径（如“安装篇 > 三、开始安装”） | 抽查父段能独立读懂“在哪一步” |
| Y-T02 | 教程 | 子块不打散步骤：编号步骤、以“：”结尾的引导句与后文、提示块与所属步骤、代码块保持在同一子块（预算内） | 抽查 3 篇长教程无断在步骤中间的子块 |
| Y-T03 | 教程 | 时间限定表述（“2025.11 更新”“目前（2022年初）”）生成父段时效提示 | 对应父段 warnings 有提示 |
| Y-C01 | 工具 | 一个工具一个父段：单工具文档整篇一个父段；合集文档每个工具小节单独成父段，标题为“分类 > 工具” | “常用软件”每个工具可单独命中，命中父段即该工具的完整介绍 |
| Y-C02 | 工具 | 工具名、用途、目录分类进入检索文本；正文只有一两句时仍能按用途召回 | “查看文件夹占用用什么软件”召回 WizTree／SpaceSniffer／TreeSize |
| Y-C03 | 工具 | 官网／下载链接和关键警告原样保留 | SDI 父段含 Alps 警告和官网地址 |
| Y-C04 | 工具 | 每篇工具条目带来源日期和时效提示，说明软件版本、下载地址可能已变化 | 检索结果 warnings 含“最后更新于 YYYY-MM-DD”的提示 |
| Y-K01 | 知识 | 父段为主题，过碎的术语小节合并到目标长度，不生成大量一两句话的向量 | 子块不足 100 字的比例明显低于叶子小节 |
| Y-K02 | 知识 | 表格按行组成为子块，表头进入每个子块的检索文本 | “重置 Winsock 的命令”命中速查表对应行组 |
| Y-K03 | 知识 | 包裹全文的单一标题下降一级 | 硬件科普按“一、CPU／二、显卡”等分父段 |

### 5.3 非功能需求

- **可维护与可扩展**：新增类别（如后续的排障、案例）只需新增结构配置或策略、在组合根注册并加入类别映射，再在清单中登记，不改导入主流程和 API。三类共用一个章节策略，差异集中在配置。
- **兼容**：现有原文 API、标准导入 API、`product_review`／`purchase_guide`／`experience_case` 的输出不变；通用解析器的增强以参数或新媒体类型隔离，并通过现有回归。
- **可测试**：平台读取通过适配器隔离，单测用合成样本和本地快照，不访问网络、数据库或模型。
- **可追溯**：父段 locator 的行号对应所取语雀 Markdown 原文；结果带原文链接、来源日期和类别（`document_schema`）。
- **安全**：语雀 Token 只来自环境变量，不写入日志、快照或仓库；真实快照放 `.runtime/` 等被忽略目录。
- **规模**：第一批约 300 个父段、600 个子块（原型估算），同步串行导入即可，不引入任务队列。

## 6. 类别识别可行性

### 6.1 可用信号

| 信号 | 可得性 | 区分力 |
| --- | --- | --- |
| 所属知识库 | 全部 | 弱：help 混合五类，textbook 混合教程、知识和工具 |
| 目录路径 | 120／122 | 局部强：“IT侠常用工具大全”下 28 篇全部是工具条目；其他目录（如“Windows 问题相关”）混合教程、知识和排障；article 目录扁平，没有分组 |
| 标题前缀与关键词 | 全部 | 中：【互助群归档】多为案例；“指南”同时用于教程和排障；推送标题口语化（“答应我，做个小公举好吗”） |
| 结构特征（编号步骤、操作动词、表格、截图密度） | 全部 | 弱：教程与知识大量混写，如“Office365 的简介、对比、注册与使用”“Bitlocker 概述”含维修实践 |
| 废弃、重复、草稿、宣传 | 需业务判断 | 内容本身无法判断，如已关闭的紫荆站教程在结构上就是一篇教程 |

### 6.2 原型评估

用有序规则链做了原型：正文过短 → 标题含说明／索引／废弃标记 → 工具目录或“用途：工具名”标题 → 案例前缀 → 排障词 → 知识词 → 教程词 → 结构特征兜底。规则是看着同一批数据写的，结果偏乐观：

| 类别 | 召回 | 精确率 |
| --- | --- | --- |
| 工具条目 | 28／31 | 28／28 |
| 操作教程 | 27／28 | 27／42 |
| 知识科普 | 12／15 | 12／15 |
| 总体准确率 | 102／122（84%） | |

20 个错误的构成：

- 废弃、重复、宣传、索引文档被判为教程或知识：10 篇。这是业务判断，内容规则无能为力。
- 排障与教程、知识互相混淆：4 篇。“排障指南”“网络问题”标题本身有歧义。
- 教程与知识互判：2 篇，两篇本身就是混写。
- 目录外的工具推荐：3 篇，如推送中的插件推荐、培训手册“常用软件”。
- 标题含“新人必读”的黑话指南被当成说明文档：1 篇。

### 6.3 结论

- **工具条目可以用代码判定**：按目录路径（`IT侠常用工具大全/**`）自动归类，精确率 100%。
- **教程、知识、排障的边界依赖语义和写作意图**：标题关键词在本数据上已经过拟合，对新文档泛化差，不适合直接放行。结构特征区分力弱。
- **是否导入（废弃、重复、草稿）是业务决定**，必须人工。
- **采用“人工清单为准、目录规则自动”的方式**：74 篇的清单由原型生成初稿后人工复核，一次性工作量很小。原型的标题规则只用于生成这份初稿，不进入导入流程。之后新增文档在试运行报告中列为“未登记”，由维护者判断后写入清单。
- **在设计上降低误判代价**：三类共用章节策略，教程与知识误判只影响少量参数，不会产生错误结构。
- **不使用 LLM 分类**：现阶段项目约定不用 LLM 识别文档类型，且文档量小，人工更可靠。

## 7. 范围外与待确认

范围外：

- 排障指南和单案例记录（后续批次）。
- 非公开知识库。
- 图片 OCR 或截图描述生成。
- 已导入文档的自动删除：当前 API 没有删除来源的入口。
- 语雀 webhook 实时同步。
- 按类别过滤检索或按场景偏好召回（需求文档 P1 的场景策略）。

已确认（2026-10-09）：

1. **培训手册的可见性**：textbook 知识库与其他知识库一样设为 `public`（2026-10-10 调整，原为 `internal`）。`internal` 只作保留值，暂不使用。
2. **旧工具条目**：全部导入，保留来源日期，并为工具条目生成带日期的时效提示（见[技术方案 6.3](technical-design.md#63-增强步骤)）；个别已失效的由清单跳过。
3. **速查表的风险等级**：由维护者在语雀原文补一列文字风险等级，导入时随表格保留；补列前导入的条目不带风险等级。

待确认：

1. **语雀 Token 与 OpenAPI**：需要具备读取 itxia 团队知识库权限的 Token，并实测 OpenAPI `body` 与网页导出是否为同一方言；若不同，只需调整方言规则。
