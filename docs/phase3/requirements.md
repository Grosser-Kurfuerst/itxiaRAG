## 2. 需要在第三阶段确定的事项

- **模型部署与数据外发**：检索系统不调用任何对话模型。线上问答由上层系统调用 LLM；规格数据由人工或外部 LLM 按[维护手册](../maintenance.md#规格填写)的填写规则填写，使用外部 LLM 时只发送公开的笔吧评测，选用哪个模型由维护者决定（[方案第 7 节](product-spec-design.md#7-规格填写)）。第二阶段“不外发原文”的约束对语雀内部文档继续有效。
- **接入位置**：检索系统的线上链路不接入 LLM。现有 `search/` 接口不变，新增独立的推荐接口；上层系统把两者作为工具调用。
- **接入方式**：2026-10-18 调整。上层问答机器人（kei-plugin-persona）只通过 MCP 使用工具，检索系统因此新增 MCP 服务，以 `search_knowledge`、`recommend_laptops` 两个工具提供检索与推荐。两个工具的参数契约改用 pydantic 模型，只定义一份：官方 SDK 的 `MCPServer`（1.x 中叫 FastMCP）据此生成工具 schema 并校验参数，REST 接口也用这份模型校验，不再另外手写工具 JSON。REST 接口的路径和返回不变，400 报错的格式随之调整。详见 [MCP 服务方案](mcp-server-design.md)。
- **评测**：沿用 D 类查询的规则标注，标注来源由 [attributes.json](../../eval/attributes.json) 改为规格文件，attributes.json 冻结，只作为试用外部 LLM 时比对填写效果的参照。条件理解的效果用模拟上层系统的评测脚本衡量：工具选择准确率、条件换算一致性、D 类端到端 P@5 与 nDCG@5（[方案 8.2 节](product-spec-design.md#82-各阶段指标)）。工具定义改为由 MCP 服务生成后，schema 的结构会变化，需要重跑模拟评测，并与 v19 基线对比（[MCP 服务方案第 6 节](mcp-server-design.md#6-评测与工具定义文档)）。
- **推荐依据**：选购指南已从库中删除，推荐类回答以评测文本为基础。
