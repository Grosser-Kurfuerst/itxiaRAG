# 第三阶段需求（草案）

状态：未开始，仅记录从第二阶段移入的功能。2026-10-12 建立，范围待第二阶段结束后细化。

第三阶段计划接入大模型（LLM），把第二阶段中依赖“理解问题”的功能改为由 LLM 完成。

## 1. 已移入的功能

| 编号 | 功能 | 来源 | 移入原因 |
| --- | --- | --- | --- |
| F2-07 | 选购条件解析与评测偏好：识别预算、重量、尺寸、显卡、接口等条件；问题带条件时，后处理优先评测父段 | [第二阶段需求](../phase2/requirements.md#32-检索质量) | 用户的说法多变（“一万以内”“七千左右”“背着不累”），规则难以覆盖；接入 LLM 后统一由 LLM 识别 |
| F2-08 | 评测结构化属性：评测来源的 metadata 记录价格、重量、尺寸、接口等属性，后处理按解析出的条件过滤或提权 | 同上 | 依赖 F2-07 解析出的条件，随 F2-07 一并移入 |

## 2. 需要在第三阶段确定的事项

- **模型部署与数据外发**：条件解析只需发送用户问题，不发送知识库原文；仍需确认使用本地模型还是外部服务，以及问题中个人信息的处理方式。第二阶段“不外发原文”的约束继续有效。
- **接入位置**：沿用第二阶段的依赖方向，LLM 解析作为查询预处理步骤，通过适配器注入组合根，不改查询主循环。
- **评测**：沿用 D 类查询与属性表 [attributes.json](../../eval/attributes.json) 的规则标注，验收条件沿用 F2-07：D 类 P@5、nDCG@5 提升，非 D 类误判条数可统计，A～F 类其余查询不下降。
- **推荐依据**：选购指南已从库中删除，推荐类回答以评测文本为基础。
