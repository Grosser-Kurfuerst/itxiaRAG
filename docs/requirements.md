# itxiaAgent 知识库总体需求

状态（2026-10-18 按各阶段需求与当前实现更新）：P0 的 F-01～F-09 已全部实现；P1 分到第二至第四阶段实施，后续阶段已实现的功能见第 4 节，P1 各项进度见第 6 节。正式库现有 171 篇来源（笔吧评测 78 篇、语雀文档 93 篇）、442 个父段、1514 个子块，规格库 78 台机型。

## 1. 定位与用户

南京大学 IT 侠为师生提供免费电脑维修、购机建议和科普服务。知识库汇集社团笔记、维修经验、获准使用的电脑评测资料，为外部 Agent 和维护者提供可定位的知识检索结果，减少资料分散、难以查找、缺少上下文与出处的问题。

当前版本聚焦“可导入、可检索、可返回上下文”，并按条件推荐机型。调用方可以提交标准化 JSON，也可以提交 HTML、Markdown 或纯文本，由预处理流水线完成解析、父子分段和子块长度控制；语雀公开库和笔吧评测公众号文章可按清单批量导入。Agent 对话、诊断、选购条件理解和最终答案生成由外部应用（上层 LLM）负责，检索系统只提供检索与推荐两个工具；OCR、非公开平台和维修登记系统的接入尚未实现。

## 2. 使用场景

| 场景 | 用户期望 | 知识库责任 |
| --- | --- | --- |
| 常见知识 | 查询系统、硬件、软件概念与操作知识 | 返回相关原文上下文及出处 |
| 购机参考 | 找到机型配置、评测表现和优缺点，或按预算、重量、接口等条件挑选机型 | 保留机型对应父段、评测日期、条件和定位，不把旧价格当实时价格；按上层换算好的原子条件筛选机型，附评测结论 |
| 维修参考 | 查找已有经验、检查步骤与注意事项 | 返回排障指南、案例记录中的经验和原始警告，不自动生成诊断或高风险操作建议 |
| 社团维护 | 加入新资料、纠正内容、更新索引、下线过时资料 | 同步导入标准化文档或经预处理的原文，去重并按稳定段落 key 更新；报告已过时的来源，由维护者确认后下线 |

## 3. 当前功能需求（P0，已全部实现）

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| F-01 | 来源、父段、子块三层存储；支持不同来源和 document_schema | 新文章类型通过规范化标识与 metadata 表达，无需每类新增表 |
| F-02 | 接收已明确父子关系的标准 JSON，校验后同步编码与保存 | 合法样本成功导入；非法关系拒绝；保留原文格式与定位 |
| F-03 | 相同来源和内容去重，稳定 key 更新当前段落 | 不重复收录；同 key 更新保留 ID；无历史版本或发布流程 |
| F-04 | 关键词与向量两路召回，RRF 融合 | 精确词项与同义查询可经不同路径得到候选；排序可追踪 |
| F-05 | 命中子块后返回完整父上下文、来源和引用 | 能判断出处和适用上下文，结果不含生成答案 |
| F-06 | Token 认证、维护权限与 public/internal 可见范围 | 普通调用方不获得内部资料；两路过滤范围一致 |
| F-07 | 保存、模型、召回和排序的可替换边界 | 应用逻辑不耦合某个模型供应商或向量数据库 |
| F-08 | 原文导入与可编排预处理；格式、结构策略和长度控制分别可替换 | HTML／Markdown／文本经显式注册的评测、购机指南或经验策略输出统一 DTO；兼容步骤可增删／调序，普通长子块拆分，不可拆单元超限明确拒绝 |
| F-09 | 召回后处理支持增加／移除步骤及调整兼容步骤的顺序 | 组合根配置有序步骤列表，默认 RRF → 父段聚合 → top_k；统一传递候选与原始路线分数，扩展不改查询主循环 |

检索已实现独立路线门槛：向量支持可选最低余弦相似度，关键词保留 `BM25 > 0` 并支持可选最低 BM25 分数；两路互不要求通过对方门槛。默认配置保持现有排序。原始 cosine／BM25 与当前排序分数分别保留，RRF 分数不视为置信度。具体方案及验收见[首期技术设计第 5 节](phase1/phase1-technical-design.md#5-检索流程)。

已实现的笔记本评测策略默认“一台笔记本一个父段”，子块按自然段合并、只用于召回，购机指南按推荐卡组织，经验文档按章节／案例组织；后续又增加了语雀教程、知识、工具条目、排障指南和整篇单案例五类策略（第 4 节）。平台类型、输入格式和内容类型独立，例如语雀导出的 Markdown 可以选择不同结构策略。具体边界、预算与扩展方式统一见[文档预处理](phase1/preprocessing.md)。

当前不纳入人工逐份审核、自动放行、发布／撤回／构建切换、审计、任务恢复、健康探针、维护模式和完整运维矩阵。只保留避免半份数据的保存事务。

## 5. 非功能需求

- **简洁与维护性**：Django 模块化单体，通过少量 Protocol、DTO 和组合根隔离真实变化点，不增加无需求支撑的抽象。
- **数据完整性**：向量和子块一一对应；模型失败不写正文，保存失败回滚当次事务；重复和更新可验证。
- **访问边界**：来源权限与文档内容分离，过滤只能缩小范围；不得提交凭据和未脱敏个人资料。提交者负责确认来源可用范围，不以模型判断代替授权。
- **模型与数据外发**：检索系统的线上链路不调用对话模型，问题理解和回答生成由上层负责；查询预处理、同义扩展和重排只在本地完成。语雀内部文档不发给外部服务；规格填写使用外部 LLM 时只发送公开的笔吧评测。
- **可追溯性**：结果包含来源、日期、段落定位、命中 ID 和排名。当前 ID 指向可更新内容，不提供不可变历史引用。
- **扩展性**：后续可更换 Embedding、pgvector、分词器、重排与来源处理器，不要求改变 API 文档输入结构。召回后处理采用统一步骤契约和有序列表；新增或调整兼容步骤不改变查询服务编排，权限范围始终由服务生成。
- **评测驱动**：检索改进每次只改一个变量，在评测上达到采纳条件才默认启用；原有类别 Hit@5、MRR@10 下降不超过约 0.02。
- **验证成本**：保留核心单元和 PostgreSQL 集成测试。真实语义效果、容量和吞吐通过实际模型与样本验证；当前不虚构性能指标。

## 7. 低优先级自进化（P2）

状态：未开始。

可以考虑自进化，但不影响当前导入／检索主线。先收集低相关、过时资料和重复失败样本，再离线评估候选规则、查询策略与处理器变更。

建议流程：人工整理失败样本 → 提出候选改动 → 在独立样本上比较正确性、成本和稳定性 → 维护者决定采用。保留可复现输入与版本说明，不让用户对话、未经确认的修复结论或模型自述自动写入权威知识；自进化不得改变资料访问范围。

此处是长期能力建议，不要求当前实现自动审核、训练、发布状态机或线上自主修改。
