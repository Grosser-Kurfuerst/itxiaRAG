# 首期需求与技术选型

本文件以最新简化范围为准，取代原 S0～S6 的治理和运维要求。细节见 [技术设计](phase1-technical-design.md) 与 [迭代一实现](phase1-iteration1-implementation.md)。

## 需求与验收

| 需求 | 当前做法 | 验收 |
| --- | --- | --- |
| 导入标准化文章 | 接收来源、文档、明确的父段与子块；同步保存 | 合成 JSON 可导入，来源和定位保留 |
| 避免重复，允许更新 | 来源稳定键 + 内容 hash；段落稳定 key | 重复不增行，同 key 更新保留 ID |
| 语义与精确词召回 | 关键词 + Embedding 向量，RRF 融合 | 各路独立生效、双路候选融合排序 |
| 返回可用上下文 | 子块检索，按最佳子块聚合完整父段 | 返回正文、来源、命中和引用 |
| 区分公开与内部资料 | Token + visibility；内部读取单独权限 | 两路召回都遵守范围，过滤不能扩大权限 |
| 扩展来源、解析、保存、排序 | DTO + Protocol + 组合根；预处理显式注册 | 用测试适配器替换，无需改写主流程 |

## 模块选型

| 模块 | 选择及理由 | 暂不采用 |
| --- | --- | --- |
| HTTP | Django + DRF；复用认证、ORM 与字段校验，只留两个入口 | Admin、OpenAPI 全套维护、独立前端 |
| 保存 | PostgreSQL 三张业务表 + JSONB 元数据/向量；少依赖、适合当前规模 | 多数据库、任务/审核/配置单例表 |
| 导入 | Python 同步应用服务，模型在事务外调用，保存一次事务 | Worker、Celery、Haystack；有真实异步需求后再加入 |
| 预处理扩展 | SourceConnector、DocumentPreprocessor、稳定 ProcessedDocument、显式策略注册 | 当前不接具体解析器、分段器或预处理模型 |
| Embedding | 兼容 OpenAI 协议的 HTTP 适配器，可连本地 Qwen 等；模型和 revision 可配置 | 将模型 SDK 写进检索业务代码、生产伪向量 |
| 关键词 | 现有 PostgreSQL 子串评分，型号词项容易检查 | PGroonga/分词器暂不部署，中文短语局限明确保留 |
| 向量 | JSONB 存储，按过滤范围精确余弦 top-N；无新数据库扩展 | pgvector/ANN 为规模升级选项；当前有线性扫描成本 |
| 融合 | RRF，避免直接相加不同尺度分数 | 默认不开 reranker；保留 Ranker 策略替换 |
| 验证 | 少量单元与 PostgreSQL 集成测试，含真实 Token 和 HTTP 协议测试 | 发布、并发、演示、历史升级验收矩阵 |

未来购机、维修场景策略、具体来源插件、真实样本质量评估等另行迭代；图谱、知识页与自进化不进入当前实现。
