# 第五阶段待改进清单

状态：待实施（2026-10-23 建立）。来源有两处：一是[召回与 Agent 输出评测扩充](../phase1/evaluation-expansion.md)的 360 题召回基线和 60 题真实 Agent 结果；二是总体需求和第二至第四阶段文档中尚未实现的需求。本文只记录问题、根因和待办，不改变各阶段文档的原有结论；某项落地后，在对应阶段文档和本文中同步状态。

评测设计和各轮结果统一记录在 [docs/phase1/evaluation-expansion.md](../phase1/evaluation-expansion.md)，不随阶段迁移：第 1～3 轮是 expanded-v1（20 题校准、360 题召回基线、60 题 Agent），[第 4 轮](../phase1/evaluation-expansion.md#第-4-轮题面去模板与分类口径调整expanded-v2)是当前的 expanded-v2。本文的验收数值以该文档最新一轮为准。

## 1. 评测结论摘要

| 层 | 结果 | 结论 |
| --- | --- | --- |
| 召回（335 个正例，strict-v2） | Hit@1 82.4%，Hit@5 95.8%；必要需求全覆盖@5 273/300 | A/B/C/E/F 已饱和；K/R/T/U 的 Hit@5 ≥ 0.975。结构性问题只剩“带机型名的复合问题，教程排不进前列”。D 类改由推荐接口回答，自然语言检索分数不再作为优化目标 |
| 推荐（D 类 29 条原子过滤） | 29/29 允许集合完全一致 | 条件筛选正确 |
| 真实 Agent（60 题 70 轮） | 任务通过 42/60，要点覆盖 94.17% | X 类 0/8；D 类 6/10；多轮 5/10 |

18 道失败题分成两类：

- **要点不完整**（8 题）：D12、D20、D22、X02、X06、X08、X09、K01；
- **要点全对，仅因“无据断言”判失败**（10 题）：A01、D11、E07、G16、K33、R33、X01、X07、X10、X11。这些断言大多是正确的常识补充，例如内存约 30° 斜插、SO-DIMM、DHCP 下发网关；真正有风险的是 G16 的型号错配。

数值是冻结 LLM 评委的原始判分。执行与评委使用同一个模型，样本不代表线上分布。X 类 8 题共用同一份教程，不是 8 个独立问题。

以上是 expanded-v1 的结果。评测集已在 2026-10-24 调整为 expanded-v2（见[扩充文档第 4 轮](../phase1/evaluation-expansion.md#第-4-轮题面去模板与分类口径调整expanded-v2)）：题面去掉原文术语，B/C 改为名称噪声和场景口语，X 改为跨文档复合任务且不再共用一份教程，G 按 `g_type` 细分，召回“全部”不含 D。下文涉及 X、G 类的验收应以 v2 重跑结果为准；X06～X11 已重写，上述失败样例中只有 X01、X02 的题面未变。

## 2. 问题与根因

### P-01 带机型名的拆装问题，召回不到通用教程

影响题目：X 类 8 题（X02/X06/X08/X09 漏掉断电；X01/X07/X10/X11 因无据断言失败）。

**现象**

- 17 道“机型 + 换内存或硬盘”题中，“断开电源和电池”需求在前 5 的覆盖为 0/17。
- 教程的混合排名有 15 题在前 20 之外。以 X06 为例，教程在关键词路排第 9、向量路排第 48。
- 所有 X 题的可见工具消息中都只有评测文章。

**只读检索复核**（正式库，top 10）：

| 查询 | 结果 |
| --- | --- |
| `惠普 HyperX 暗影精灵 PRO 16 内存 更换 安装 拆机`（Agent 实际查询） | 10 条全是评测，9 条是其他机型 |
| `笔记本 加装内存 步骤` | 8 条评测、1 条知识科普，没有教程 |
| `笔记本 更换内存 安全 注意事项` | 同上 |
| `笔记本 拆机 更换配件 前 断电 电池` | 教程“更换配件”的两个父段排第 1、2 |

**根因**

1. **评测模板句竞争**：78 篇评测中，50 篇含“可自行加装”，34 篇含“内存插槽”；非评测资料里这两句只出现过 1 次。“内存 + 加装/更换”类查询在关键词和语义两路都被评测压住。
2. **词汇鸿沟**：断电要求在教程“更换配件”的“必须操作”父段（528 字），正文不含“内存”，标题也不含配件名。安装步骤在“常见的硬件更换”父段（1057 字），混了 6 种配件，内存只占一句。用户问“换内存”时不会用“更换配件、断电”这些词。
3. **问题是复合的**：“机型有没有插槽”在评测里，“通用怎么装”在教程里，单次查询只能命中一侧。43/60 题 Agent 只检索了一次；X08、X09 追问时检索了第二次，但仍带机型名。
4. **截断是次要因素**：见 P-05。被截掉的段落同样是其他机型评测，不是 X 类的主因。

**后果**：模型拿到“有两个插槽”后凭常识补步骤，要么漏掉电池，要么补对了但没有出处。只在提示词里要求二次检索不能解决问题，因为不带机型名的通用查询同样排不出教程。

### P-02 Agent 缺少拆装安全规则

影响题目：X02、X06、X08、X09。

问题提示词（[工具定义](../../products/tool-definitions.md)）没有要求“拆装前必须断开电池”。X08 追问“不拔内置电池能不能换”时，回答“可以操作”，只把断开电池说成“最好”。这种表述属于安全条件被弱化，不只是证据缺失。

### P-03 聊天人设与推荐依据要求冲突

影响题目：D12、D20、D22。

推荐的机型全部满足硬条件。`recommend_laptops` 已返回 `price_kind`、`price_date` 和 `review.source.url`，失败都在“依据”一项：

- D22 第一轮：第三台没附链接；
- D12、D20：某台的价格没说明是评测参考价；
- D20 第二轮：多轮中继续推荐的旧机型没有再附链接。

根因是 persona 人设要求“通常一到两句话、最多 500 字、不用列表”。一条公众号链接约 110 字符，这三题的回答为 351–395 字，推荐 3 台时放不下每台的链接和价格口径。评分标准要求每台、每轮都附来源，与聊天场景冲突。另有评委误判，见 P-07。

### P-04 缺少时效与型号边界规则

影响题目：K01、G16。

- **K01**：检索正确，门户“修改服务”段可见。原文写“学校网络**现在**四设备同时在线 20 块钱每个月就封顶了”，来源日期为 2024-09-20；模型改写成“一般是……封顶”，当成了现行规则。提示词只对推荐结果说明“价格是评测时的价格”，对 `search_knowledge` 结果没有时效要求。`source_date` 虽已返回，但淹没在元数据中。
- **G16**：模型承认资料没有 2027 款的最大内存容量，却把 2026 款评测中的双插槽说成“这款”的配置。资料年份与问题年份不符时，没有规则要求明说。对应需求 F2-09（型号不符标记）。

### P-05 MCP 检索输出被元数据占满

影响范围：全局，属次要因素。

- 60 题中有 54 条工具消息达到 12000 字符截断上限（persona 的 `tools_result_max_chars`）。
- 截断后，正文只占可见内容的约 42%（27%–55%）。其余是 `matches`、`evidence_id`、`route_scores`、`ranks`、`locator` 和各类 id，这些对大模型没有用。
- `top_k=5` 时，可见段落中位数为 3 段，最少 2 段。一篇评测父段约 2300 字，两三篇加上元数据就会被截断。
- 截断后的 JSON 不完整，`source_date` 等关键字段可能看不到。

### P-06 无据断言的判分口径过严

影响题目：A01、D11、E07、K33、R33、X01、X07、X10、X11。

当前规则是只要有一条断言不在可见资料中，整题就判失败，把“正确常识补充”和“可能出错的具体数值、操作、型号”混为一谈。这样后续改进很难区分是产品变好了，还是模型变保守了。

### P-07 LLM 评委存在误判与漏检

已确认的问题（见 `.runtime/eval/expanded-v1/agent-implementation-audit.json`）：

- D20：误读全局 `unknown` 统计，把有数据的续航判为无据；
- D22 第二轮：违反冻结的评委规则，额外要求评测日期；
- X06：漏标安装步骤缺少出处。

评委目前只适合辅助定位问题，关键失败需要人工复核。

## 3. 待改进任务
