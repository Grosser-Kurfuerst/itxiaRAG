# 第四阶段需求（草案）

状态：进行中。2026-10-14 建立，来源于对当前导入能力的评估；F4-01、F4-02 已完成（2026-10-14），其余项范围待第三阶段结束后细化。

第四阶段补齐资料导入的维护缺口。现有导入链路已经能把语雀公开库、公众号评测和零散资料导入，并在内容更新时整篇替换、内容未变时跳过 Embedding；缺口主要在“导入之后如何与来源保持一致”和人工维护成本。

## 1. 现状

| 资料 | 已有能力 |
| --- | --- |
| 语雀公开库 | 按清单批量导入，报告未登记文档，支持试运行、`--only`、离线快照，五种类别均已接入 |
| 公众号评测 | 经搜狗自动下载或人工保存网页后离线导入，身份按永久链接确定；机型规格按[维护手册](../maintenance.md#规格填写)填写并导入 |
| 零散资料 | 原文 API 接收 HTML、Markdown、纯文本，标准 API 接收已切分的 JSON |
| 更新 | 同一来源内容变化时整篇替换并保留 key 不变的父段和子块 ID；内容未变返回 `reused`，不调用 Embedding、不写库 |

## 2. 功能需求

按优先级排列。**必做**直接影响检索结果的正确性；**按需**在出现具体问题后再做；**暂缓**在当前规模下由人工流程承担。

### 2.1 必做：来源下线与对账

| 编号 | 功能 | 现状 | 验收 |
| --- | --- | --- | --- |
| F4-01 | 过期来源对账：导入报告列出“库中存在，但清单已标 `skip` 或来源已不存在”的来源 | 语雀删除文章后，导入只提示“在文档列表中找不到”（[sources/importing.py](../../sources/importing.py)）；清单改为 `skip` 后库中内容保留。过时、废弃内容会继续被检索到，评测答案可能指向不应存在的来源 | 语雀、公众号批量导入都输出过期来源清单，包含定位符、标题和原因；只报告，不自动删除；只在不带 `--only` 的正式导入时对账，避免误报。已完成（2026-10-14） |
| F4-02 | 来源下线命令：按来源类型和定位符删除来源及其父段、子块 | 只能在 Django shell 中手写查询删除（[维护手册 2.6](../maintenance.md#26-下线或删除来源)） | 支持试运行，列出将删除的来源、父段数和子块数；正式删除在一个事务内完成；对 F4-01 报告的来源可直接使用；维护手册 2.6 改为使用该命令，并保留备份与同步查询集、规格文件的步骤。已完成（2026-10-14），命令为 `delete_source` |

对账只比较清单与库中已有来源，不引入删除状态或回收站；误删依靠删除前备份恢复。技术方案见[来源对账与下线方案](source-reconciliation-design.md)。

### 2.2 按需

| 编号 | 功能 | 现状 | 做法 |
| --- | --- | --- | --- |
| F4-03 | 例行更新：定期发现语雀原文变更 | 没有定时任务和变更通知，只能人工全量重跑 `import_yuque`；未变文章已不计算向量，但仍逐篇读取和预处理 | 先在维护手册写明重跑频率与检查项；人工重跑出现遗漏后再加定时任务。不按语雀更新时间做增量判断，避免额外状态 |
| F4-04 | 超长小节的处理：语雀文章某节超过长度上限时报 `SEMANTIC_UNIT_TOO_LARGE`，现有处理方式是在原文补小标题 | 语雀原文不由本项目维护，无法补标题时只能 `skip`；当前清单没有因此失败的文章 | 出现失败样本后，再评估在对应策略中按段落切开超长小节，不提前实现 |

### 2.3 暂缓

| 编号 | 缺口 | 影响 | 暂缓原因与重新考虑的条件 |
| --- | --- | --- | --- |
| F4-05 | 截图内容丢失：截图只留下“原文含未转写的截图”警告，带说明文字的图片保留为 `[图片：说明]` | 只写在截图里的步骤和界面文字检索不到 | OCR 和图片转写不在当前范围，且需要本地模型；出现因截图缺失导致的失败样本，并有获准的本地模型时再评估 |
| F4-06 | 公众号接入成本：自动下载依赖搜狗搜索，遇验证码需稍后重跑，每期同名的文章搜不到只能人工保存；新评测需人工填写 `entity_title` 和规格记录 | 新增评测的人工步骤多 | 当前数量下可接受；规格填写已有可交给 LLM 代理执行的步骤。新增频率明显上升时再评估 |
| F4-07 | API 来源不能作为评测答案：评测器只能按语雀 `库/slug` 或评测机型名定位答案 | 零散资料无法纳入召回回归 | 零散资料数量很少；需要长期维护的资料走清单导入。数量增多时再扩展别名格式 |

## 3. 不进入第四阶段

沿用[第二阶段需求第 5 节](../phase2/requirements.md#5-不进入第二阶段)的判断：

| 项 | 原因 |
| --- | --- |
| 语雀非公开库 | 需要团队 Token 和授权 |
| 维修登记系统连接器 | 没有可读的登记系统，脱敏规则未定 |
| PDF、Word、附件 | 原文 API 只接收文本类格式；清单中“仅含链接或附件”的文档已标 `skip` |
| 抓取任务队列、审核发布 | 项目约定不实现 |

## 4. 完成定义

- 按需项有失败样本时已处理，或记录不处理的结论；
- 维护手册 2.2、2.6 已同步；
- 全量测试通过。
