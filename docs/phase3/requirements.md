# 第三阶段需求（草案）

状态：实施中。2026-10-12 建立；F2-08 的规格库与推荐接口已实现（[机型规格库方案](product-spec-design.md) P1），工具定义与上层接入验证见方案 P3。

第三阶段计划接入大模型（LLM），把第二阶段中依赖“理解问题”的功能改为由 LLM 完成。

## 1. 已移入的功能

| 编号 | 功能 | 来源 | 移入原因 |
| --- | --- | --- | --- |
| F2-07 | 选购条件解析与评测偏好：识别预算、重量、尺寸、显卡、接口等条件；问题带条件时，后处理优先评测父段 | [第二阶段需求](../phase2/requirements.md#32-检索质量) | 用户的说法多变（“一万以内”“七千左右”“背着不累”），规则难以覆盖；接入 LLM 后统一由 LLM 识别。2026-10-12 改为由上层 LLM 识别，检索系统只提供工具定义 |
| F2-08 | 评测结构化属性：评测来源的 metadata 记录价格、重量、尺寸、接口等属性，后处理按解析出的条件过滤或提权 | 同上 | 依赖 F2-07 解析出的条件，随 F2-07 一并移入。2026-10-12 改为规格表 `product_spec` 与推荐接口 `POST /api/v1/products/recommend/`，按原子条件过滤，已实现 |

2026-10-12 方案调整：问题类型判断与选购条件解析（F2-07）不在检索系统中实现，由上层接入的 LLM 通过工具调用完成；检索系统新增按原子条件过滤的推荐接口和规格库（F2-08），并提供工具定义。职责划分见[机型规格库方案第 3 节](product-spec-design.md#3-职责划分上层-llm-与检索系统)。

## 2. 需要在第三阶段确定的事项

- **模型部署与数据外发**：检索系统不调用任何对话模型。线上问答由上层系统调用 LLM；规格数据由人工或外部 LLM 按[维护手册](../maintenance.md#规格填写)的填写规则填写，使用外部 LLM 时只发送公开的笔吧评测，选用哪个模型由维护者决定（[方案第 7 节](product-spec-design.md#7-规格填写)）。第二阶段“不外发原文”的约束对语雀内部文档继续有效。
- **接入位置**：检索系统的线上链路不接入 LLM。现有 `search/` 接口不变，新增独立的推荐接口；上层系统把两者作为工具调用。
- **评测**：沿用 D 类查询的规则标注，标注来源由 [attributes.json](../../eval/attributes.json) 改为规格文件，attributes.json 冻结，只作为试用外部 LLM 时比对填写效果的参照。条件理解的效果用模拟上层系统的评测脚本衡量：工具选择准确率、条件换算一致性、D 类端到端 P@5 与 nDCG@5（[方案 8.2 节](product-spec-design.md#82-各阶段指标)）。
- **推荐依据**：选购指南已从库中删除，推荐类回答以评测文本为基础。
